# Safe Check

确认版本、审计范围、入口、信任边界、数据分类、身份/租户模型与关键资产。依据风险追踪端到端流程，不孤立扫描文件，也不把 CLI 服务强行纳入前端视觉审查。

## 按相关性检查

**安全与数据暴露**：服务器端认证/授权、越权和跨租户访问；客户端、API、日志、URL、存储、Cookie、源映射和分析链路泄密；SQL/命令/模板/提示/脚本注入；XSS、CSRF、SSRF、上传、重定向和路径遍历；会话、令牌、数据库/存储桶规则、CORS、Webhook 与第三方集成的实际信任边界。不能以客户端校验替代服务端约束。

**并发与状态完整性**：重复点击、重试和并发请求的幂等性；支付、消息、任务等不可逆副作用；陈旧状态、丢失更新、乱序响应、乐观更新回滚；缓存一致性、监听器/定时器/请求清理；相关的多标签页、多设备和弱网行为。

**可靠性**：错误吞没、未处理拒绝、无限加载/重试、不完整回滚；空、错误、离线、超时和部分成功状态；API 可空性、排序、时序假设；内存泄漏及实际影响用户的性能瓶颈。

**适用的 UI**：语义、键盘/焦点、可访问名称、对比度、缩放、触摸目标、减少运动、屏幕阅读器和错误恢复；按项目约定检查 WCAG 等标准。检查间距、排版、响应式、组件状态与交互是否一致，不为凑审计项提出纯偏好性改版。

## 证据与权限

对登录、权限、敏感读写、文件处理、支付等高风险路径贯穿客户端、API、服务端和持久化层。扫描告警只是线索；结合可达性、输入控制、运行约束和现有防护确认问题。

默认不修改代码、数据、配置或部署。修复需用户授权，并用回归测试证明。只在获授权范围内做必要的非破坏性验证；不执行破坏性利用或访问无授权数据。证据脱敏，不复述完整密钥、令牌、Cookie、个人数据等敏感值。

## 输出

按 `Critical`、`High`、`Medium`、`Low`、`Informational` 排列实际发现，说明已确认或待验证。每项给出位置、可达的攻击/故障路径、影响、防护不足、最小修复及回归验证；严重度与置信度分开，不把所有静态告警升级为漏洞。

已排除的告警只在能解释重要疑点时附记，不混入待修复清单。结尾明确阻止发布的问题、数据泄露/授权覆盖情况、未验证盲点及发布前必要修复。证据不足可以无法判断；“未发现”不等于“绝对安全”。
