# 语音推理优化

先明确目标是首包、持续播放、吞吐、内存还是成本，并保持用户给定的音质/识别率约束。模型、设备、并发、文本/音频长度、精度和计时起终点应可复现；已有信息不重复询问。

```text
采集 / endpointing -> ASR -> LLM -> TTS -> 传输 / 播放
                         只重叠具有明确依赖与取消语义的阶段
```

## 测量与实验

1. 记录端到端及各阶段时间，包括排队、首次音频、chunk 间隔、播放欠载和尾延迟。区分模型 RTF 与用户实际听到声音的时间。
2. 用时间线找关键路径，不直接相加重叠阶段，也不把尚未完成的依赖视为已被流水线消除。
3. 从[技术与历史案例](references/techniques.md)选择匹配瓶颈的一个候选：endpointing、缓冲、批处理、融合、量化或部署。案例数值不是默认阈值。
4. 在真实并发下检查质量、错误、取消、打断、背压和内存。量化误差预算与流式分块策略必须来自任务，不默许 WER 上升或首包超标。
5. 对比同一基线；GPU 热点需要进一步归因时才进入 profiling 工作流。没有设备或 trace 时给假设与最小补测，不声称优化已通过。

分析请求不改代码；不默认购买算力、调用付费服务或上传音频。交付主要瓶颈、验证过的改动与前后指标、质量结果、复现方法和剩余约束。
