保存值得反复查阅的资料，以及「为什么留、什么时候用」。按主题组织，不按网站或收藏日期堆积。

## 主题

- [GPU 优化](gpu/README.md)：CUDA kernel、性能测量与推理系统。

## 怎么收录

普通链接直接加到主题页，至少写**原文链接 + 一句收藏理由**。重要教材、需要章节定位或已有阅读笔记的资料，
单独放在 `<主题>/<英文短名>.md`，主题页链接到卡片。先搜索标题或原文 URL 去重；跨主题引用同一卡片，不复制正文。
只在确有资料时新建主题，不预建空目录、标签体系或数据库。

重要资料沿用下面的简短模板。未知信息写「未记录」，不要猜测作者、日期、阅读进度或实验结果。

```markdown
# 资料标题

原文：完整 URL
作者 / 来源：未记录
收录日期：YYYY-MM-DD
最近核对：YYYY-MM-DD；说明只检查了链接、目录，还是具体内容
阅读状态：未记录
官方源码 / 备用入口：有则填写，没有则省略

## 为什么收藏

一句话说明它解决什么问题，以及适合什么时候查。

## 重点入口与适用边界

按需要留下章节链接、硬件 / 软件版本限制。推荐阅读顺序属于整理建议，不当作原文结论。

## 阅读与实践记录

尚未记录。阅读后追加自己的结论；实验附环境、代码版本、测量口径及结果。
```

## 怎么查、怎么维护

从主题页进入，再按需读卡片；也可以在仓库根目录用 `rg -n 'TMA|GEMM|vLLM' knowledge/` 搜索。
新增或更新时核对原始页面，并记录检查日期与范围。「能打开」不等于读完、内容正确或已经复现。
链接失效时保留标题、旧 URL 和摘要，标明失效日期，再补官方新地址；不要直接删除重要资料。

资料与操作技能分开：这里保存来源和阅读记录；可执行的方法保留在 [领域技能](../home/skills/)。
Agent 只读取相关主题和资料卡，不把整个知识库或网页内容默认注入上下文。

## 保存边界

本目录位于仓库根目录，不属于 `home/`，不随 dotfiles 安装复制到 `$HOME`。
提交到 Git 后可以追踪卡片历史；推送后才有远端副本。Git 保存的是链接和自写笔记，**不是原网页全文备份**。
重要资料优先保留官方源码或备用入口；全文或代码归档需先核对许可，本次不抓取整站或添加自动任务。
只收公开资料，不写入令牌、带凭据的 URL、私有地址或未经允许发布的内容。
